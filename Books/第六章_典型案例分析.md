# 第六章 典型案例分析

本章围绕 HydroSIS 仓库自带的示例资源，构建三个具有代表性的典型案例：
基准流域模拟、调度情景对比与精度评价复盘，以及二次开发视角的配置扩展。
每个案例均给出输入配置、执行流程、核心源码位置及结果解读，帮助读者在不运行程序的情况下掌握框架的端到端逻辑。

## 6.1 案例选型原则与示例资源概览

HydroSIS 提供的示例配置 `config/example_model.yaml` 涵盖了 DEM 划分、产流与汇流模型库、参数分区、情景修改及评价计划，是构建典型案例的最佳起点。【F:config/example_model.yaml†L3-L131】
配套的示例工作流脚本 `examples/run_sample_workflow.py` 则封装了加载配置、生成观测、运行情景、落盘结果和汇报的全流程入口，便于对照源码理解每一步的职责划分。【F:examples/run_sample_workflow.py†L35-L182】

在挑选案例时，本章遵循以下原则：

1. **覆盖核心能力**：至少涉及模型构建、情景切换、数据持久化和指标评价等主流程函数，以确保读者掌握框架的关键接口。
2. **强调可扩展性**：展示如何沿用配置结构新增模型或情景，凸显 HydroSIS 在二次开发场景中的灵活性。
3. **输出可验证性**：虽然不运行代码，但仍通过阅读示例脚本中打印的汇总信息与目录规划，推演结果内容与格式，帮助读者验证自己的理解是否与框架一致。

下表概括了三大案例的定位：

| 案例 | 目标 | 关键源码/配置 | 关注要点 |
| --- | --- | --- | --- |
| 案例一：基准模拟复盘 | 熟悉模型加载与流域累积逻辑 | `HydroSISModel.from_config`、`run_workflow` | 子流域参数映射、径流累积、输出目录结构 |
| 案例二：调度情景对比 | 理解情景参数覆盖与指标排序流程 | `ModelConfig.apply_scenario`、`ModelComparator.compare` | 情景参数修改、观测对齐、指标聚合 |
| 案例三：扩展化情景定制 | 演示如何新增情景与定制评价计划 | `ScenarioConfig`、`EvaluationConfig` | 配置增量维护、报告生成路径、团队协作建议 |

## 6.2 案例一：基准模拟复盘

### 6.2.1 配置拆解

基准案例直接复用 `example_model.yaml` 的默认设置：

- **流域划分**：`precomputed_subbasins` 定义了四个子流域，记录面积、下游指向以及默认的产流、汇流模型标识，为模型初始化提供结构化输入。【F:config/example_model.yaml†L8-L33】
- **模型库**：`runoff_models` 与 `routing_models` 段列出可复用的算法配置，诸如 SCS 曲线数法、XinAnJiang 与 Muskingum 路由，后续实例化时按 ID 引用。【F:config/example_model.yaml†L34-L83】
- **参数区**：`parameter_zones` 通过控制点（如子流域 SB1、SB3）组织参数覆盖范围，HydroSISModel 在初始化时会将对应参数写入子流域对象。【F:config/example_model.yaml†L84-L102】【F:hydrosis/model.py†L32-L51】
- **I/O 配置**：`io` 段指定降雨驱动、观测数据、结果与报告目录，示例脚本在运行前会解析为绝对路径，确保各平台目录一致。【F:config/example_model.yaml†L104-L109】【F:examples/run_sample_workflow.py†L142-L150】

### 6.2.2 执行流程

1. **加载配置**：`_load_model_config` 优先尝试 YAML，若环境缺少 PyYAML 则回退到 JSON，保证示例可在纯标准库环境运行。【F:examples/run_sample_workflow.py†L35-L75】
2. **实例化模型**：`HydroSISModel.from_config` 根据配置生成子流域、参数区与模型库，并自动执行参数覆盖 `_assign_zone_parameters`，确保每个子流域持有 `runoff_model`、`routing_model` 键。【F:hydrosis/model.py†L32-L91】
3. **运行基准情景**：`run_workflow` 首先调用 `_run_model` 执行基准模拟，内部先产流再汇流，随后利用 `accumulate_subbasin_flows` 下泄汇流结果，形成包含上游贡献的累积序列。【F:hydrosis/workflow.py†L197-L214】【F:hydrosis/model.py†L70-L104】
4. **结果落盘**：当 `persist_outputs=True` 时，工作流将基准结果写入 `results/example_run/baseline`，每个 CSV 包含索引与流量列，便于后续绘图或校验。【F:hydrosis/workflow.py†L215-L221】【F:hydrosis/io/outputs.py†L10-L22】
5. **终端反馈**：脚本在完成后打印每个子流域前五个累积径流值以及总体指标（若存在观测），帮助用户快速对照理论结果与实际输出。【F:examples/run_sample_workflow.py†L164-L179】

```mermaid

    A[配置加载] --> B[HydroSISModel.from_config]
    B --> C[model.run]
    C --> D[model.accumulate_discharge]
    D --> E[write_simulation_results]
    E --> F[终端打印与人工复核]
```

### 6.2.3 结果解读

尽管不直接执行脚本，我们仍可通过代码推理以下要点：

- `write_simulation_results` 采用固定的 CSV 结构，意味着每个子流域的输出文件可直接被电子表格或绘图脚本读取。【F:hydrosis/io/outputs.py†L18-L23】
- `_ensure_observations` 在缺乏观测数据时，会调用基准模型生成累积径流并注入轻微扰动，确保后续评价步骤有数据可用，这也解释了示例运行能够自动生成报告的原因。【F:examples/run_sample_workflow.py†L78-L123】
- 当评价配置为空时，`_build_evaluator` 会回退到默认指标集（RMSE、MAE、PBIAS、NSE），因此无需手动维护指标列表即可获取常见评估结果。【F:hydrosis/workflow.py†L75-L89】

通过案例一，读者可以完整理解“配置 → 模型 → 结果”的流水线，并熟悉输出目录结构，为后续情景分析与指标比对奠定基础。

## 6.3 案例二：调度情景对比与指标排序

案例二聚焦于 `reservoir_reoperation` 情景，展示框架如何在不修改源码的情况下，通过配置实现参数替换、情景运行与指标排名。

### 6.3.1 情景定义

`scenarios` 段列出了 `reservoir_reoperation`，其修改包括：

- 将 SB3、SB4 的汇流模型替换为 `muskingum_outlet`，模拟下游加大泄洪能力的调度策略；
- 将 SB1 的产流模型调整为 `upland_adjusted`，反映上游控制区的曲线数增加，使降雨转化为径流的效率更高。【F:config/example_model.yaml†L111-L122】

这些修改在运行时通过 `ModelConfig.apply_scenario` 应用到模型的子流域对象上，本质是对 `Subbasin.parameters` 的局部覆盖。【F:hydrosis/config.py†L185-L192】【F:hydrosis/model.py†L18-L27】

### 6.3.2 工作流执行

`run_workflow` 在完成基准模拟后，会遍历请求的情景 ID：

1. 深拷贝配置，实例化新的 `HydroSISModel`，保证情景之间互不干扰；
2. 调用 `apply_scenario` 更新模型内的子流域参数；
3. 再次运行 `_run_model`，得到情景的局部、累积与参数区流量序列，并存储于 `ScenarioRun` 结构中。【F:hydrosis/workflow.py†L200-L214】【F:hydrosis/workflow.py†L54-L72】

当持久化启用时，每个情景的累积结果会被写入 `results/example_run/<scenario_id>`，形成与基准一致的 CSV 组织方式，方便对比分析。【F:hydrosis/workflow.py†L215-L221】

### 6.3.3 指标评价与排名

如果观测（或合成观测）存在，工作流将：

- 调用 `ModelComparator.compare` 遍历所有模拟结果，逐子流域计算指标，再用均值聚合成整体评分；
- 针对 `baseline_vs_reoperation` 计划，仅比较 SB3、SB4 两个控制点，并按照 RMSE 的绝对值进行排序；
- 通过 `ModelComparator.rank` 根据指标取向（最小化或最大化）输出排名列表，为报告与决策提供依据。【F:hydrosis/evaluation/comparison.py†L23-L127】【F:config/example_model.yaml†L123-L131】

`generate_report=True` 时，`run_workflow` 会在 `reports_directory` 下写入 `evaluation.md`，并在需要时自动创建图表目录，这些操作统一由工作流负责，无需用户额外编写 I/O 代码。【F:hydrosis/workflow.py†L232-L259】

### 6.3.4 结果研判思路

即便不运行脚本，也可以依据算法逻辑推断：

- **上游响应**：SB1 采用更高曲线数，将增强暴雨后径流系数，预计情景输出在洪峰期会高于基准。
- **下游调度**：SB3、SB4 改用 `muskingum_outlet`，旅行时间与权重不同于基准配置，可能导致洪峰推迟或削峰，这会直接反映在累积径流 CSV 的数值序列上。
- **指标变化**：若合成观测以基准结果为基础轻微扰动，则基准模型的 RMSE、MAE 等指标应优于情景；因此排序结果可能显示基准排名靠前，这与调度策略偏离观测的情形一致。

通过案例二，读者可以掌握 `run_workflow` 在执行情景模拟与评价时的控制流，理解配置驱动参数替换的关键机制，为多情景分析提供思路。

## 6.4 案例三：扩展化情景定制指南

案例三站在二次开发角度，指导如何在现有配置和脚本基础上，新增自定义情景与评价计划，并保持与示例工作流的兼容性。

### 6.4.1 新增情景步骤

1. **编写配置**：在 `scenarios` 列表中追加新的情景，如 `extreme_precipitation`，指定目标子流域的产流参数（例如提高 `curve_number`）和调度策略。
2. **引用模型库**：若需要全新算法，可在 `runoff_models` 或 `routing_models` 增加对应配置，并在 `parameter_zones` 中指派默认值，确保 `HydroSISModel` 初始化后能找到所需模型。【F:config/example_model.yaml†L34-L102】【F:hydrosis/model.py†L70-L91】
3. **执行脚本**：示例脚本默认执行配置中列出的全部情景，无需修改 Python 代码；若只想运行部分情景，可在调用 `run_workflow` 时传入 `scenario_ids` 参数，或为脚本新增命令行选项。

### 6.4.2 自定义评价计划

`EvaluationConfig` 支持配置多个比较方案，每个方案可指定对比模型、参考序列、关注子流域与排名指标：

- 若新增情景，需要在 `comparisons` 中列入新的模型 ID，以便与基准或其他方案比较；
- `ranking_metric` 可切换为 `nse` 或 `pbias`，`ModelComparator` 会自动根据指标取向（最大化或最小化）排序结果。【F:hydrosis/config.py†L20-L76】【F:hydrosis/evaluation/comparison.py†L92-L109】
- `run_workflow` 会遍历全部比较方案并返回 `EvaluationOutcome` 列表，供后续生成报告或制作仪表盘使用。【F:hydrosis/workflow.py†L224-L239】

### 6.4.3 结果持久化与知识沉淀

- **数据仓储**：`write_simulation_results` 以子流域 ID 命名 CSV 文件，可直接同步到对象存储或版本化的实验目录，形成结构化档案。【F:hydrosis/io/outputs.py†L18-L23】
- **报告协作**：`generate_evaluation_report` 的输出路径可通过配置指定，团队成员可将报告目录纳入版本控制或知识库，结合 Markdown 协作审阅。【F:hydrosis/workflow.py†L240-L259】
- **终端提示**：示例脚本打印的指标与路径信息，是检查自动化流程是否完成的重要信号，可在 CI/CD 中捕捉这些文本以实现自动通知。【F:examples/run_sample_workflow.py†L164-L180】

### 6.4.4 二次开发注意事项

- **配置回退**：`_load_model_config` 提供了 YAML→JSON 的容错，若团队引入更复杂的配置格式，应考虑同步维护回退逻辑，以保证在轻量环境下仍能运行示例。【F:examples/run_sample_workflow.py†L35-L75】
- **观测生成**：`_ensure_observations` 的扰动策略适合教学和入门测试，实际项目应替换为真实观测或更合理的合成方法，可参考函数内部流程编写自定义生成器。【F:examples/run_sample_workflow.py†L78-L123】
- **模型解耦**：`HydroSISModel` 在运行时为每个子流域深拷贝模型实例，确保参数修改互不影响，这一设计值得在自定义模块中保持，以避免多情景运行时的状态污染。【F:hydrosis/model.py†L70-L91】
