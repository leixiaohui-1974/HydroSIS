# HydroSIS 用户手册

## 简介

HydroSIS (Hydrological Simulation and Information System) 是一个配置驱动的水文模拟系统，提供从流域划分到径流模拟的完整工作流。

### 主要特性

- ✅ **配置驱动**: 所有参数通过YAML配置文件管理，零硬编码
- ✅ **全面验证**: 内置验证框架，确保数据质量
- ✅ **并行计算**: 支持多核并行，提升大规模模拟效率
- ✅ **标准输出**: GeoJSON、CSV等标准格式，易于集成
- ✅ **可扩展性**: 模块化设计，易于添加新功能

## 工作流步骤

HydroSIS的完整工作流包含11个步骤：

### Step 1: 子流域划分
**功能**: 基于DEM和流向数据划分子流域

**输入**:
- DEM (数字高程模型)
- 流向栅格

**输出**:
- `subbasins.geojson`: 子流域边界
- `subbasin_statistics.csv`: 子流域统计

**配置示例**:
```yaml
step_01_subbasins:
  min_area_km2: 10.0
  max_area_km2: 500.0
```

---

### Step 2: 河网提取
**功能**: 从子流域边界提取河网拓扑

**输出**:
- `river_network.geojson`: 河网线要素
- `network_topology.json`: 拓扑关系

---

### Step 3: 参数分区
**功能**: 基于土地利用、土壤等特征进行参数分区

**输出**:
- `parameter_zones.geojson`: 参数分区
- `zone_statistics.csv`: 分区统计

**配置示例**:
```yaml
parameter_zoning:
  n_clusters: 6  # 分区数量
  features:
    - slope
    - land_use
    - soil_type
```

---

### Step 4: 横断面提取
**功能**: 沿河道提取横断面数据

**输出**:
- `cross_sections/*.csv`: 各子流域横断面数据

---

### Step 5: 雨量站优化
**功能**: 优化雨量站空间分布

**输出**:
- `optimized_gauges.geojson`: 优化后的雨量站分布
- `gauge_density_analysis.csv`: 密度分析

**配置示例**:
```yaml
rain_gauge:
  target_density: 0.01  # 1站点/100km²
  min_distance_m: 1000  # 最小站间距
  random_seed: 42
```

**运行命令**:
```bash
python optimize_rain_gauges_refactored.py \
    --config config/workflow_config.yaml
```

---

### Step 6-8: 降雨数据处理
**功能**: 降雨数据插值、时空分析

**输出**:
- 各子流域降雨时间序列
- 降雨空间分布图
- 质量检查报告

---

### Step 9: HBV径流模拟
**功能**: 使用HBV模型进行径流模拟

**输出**:
- `runoff_results/*.csv`: 各分区径流序列
- `runoff_summary.csv`: 径流汇总统计

**HBV参数配置**:
```yaml
hbv_parameters:
  FC: 300      # 田间持水量 (mm)
  BETA: 2.0    # 形状系数
  LP: 0.7      # 蒸散发阈值
  K0: 0.1      # 快速消退系数
  K1: 0.05     # 中速消退系数
  K2: 0.01     # 慢速消退系数
  PERC: 2.0    # 渗透速率 (mm/h)
  UZL: 50.0    # 上层水库阈值 (mm)
```

**运行HBV校准**:
```bash
python calibrate_hbv_all_zones.py \
    --config config/workflow_config.yaml \
    --validation-config config/validation_criteria.yaml
```

**使用并行HBV**:
```python
from hydrosis.runoff.parallel_hbv import run_hbv_parallel, ParallelHBVConfig

config = ParallelHBVConfig(max_workers=4)
results = run_hbv_parallel(zones, precipitation_data, hbv_params, config)
```

---

### Step 10: 洪水演进
**功能**: 河道洪水演进计算

---

### Step 11: 结果可视化
**功能**: 生成图表和地图

## 配置文件详解

### 主配置文件: `config/workflow_config.yaml`

```yaml
# 项目名称
project_name: upper_truckee_river

# 目录配置
directories:
  base_results: results/${project_name}
  base_data: data
  step_01_subbasins: ${base_results}/step_01_subbasins
  step_02_river_network: ${base_results}/step_02_river_network
  step_03_parameters: ${base_results}/step_03_parameters
  step_04_cross_sections: ${base_results}/step_04_cross_sections
  step_05_rain_gauges: ${base_results}/step_05_rain_gauges

# HBV模型参数
hbv_parameters:
  FC: 300      # Field capacity (mm)
  BETA: 2.0    # Shape coefficient
  LP: 0.7      # Evapotranspiration threshold
  K0: 0.1      # Recession coefficient 0
  K1: 0.05     # Recession coefficient 1
  K2: 0.01     # Recession coefficient 2
  PERC: 2.0    # Percolation (mm/h)
  UZL: 50.0    # Upper zone threshold (mm)
  TT: 0.0      # Temperature threshold (°C)
  CFMAX: 3.0   # Degree-day factor
  CFR: 0.05    # Refreezing coefficient
  CWH: 0.1     # Water holding capacity

# 雨量站配置
rain_gauge:
  target_density: 0.01        # 目标密度
  excellent_density: 0.02     # 优秀
  good_density: 0.01          # 良好
  fair_density: 0.005         # 一般
  poor_density: 0.002         # 较差
  min_distance_m: 1000        # 最小距离
  buffer_distance_m: 500      # 缓冲距离
  random_seed: 42             # 随机种子
  max_iterations: 1000
  optimization_method: "random_uniform"

# 并行计算配置
parallel:
  max_workers: 4
  show_progress: true
```

### 验证标准配置: `config/validation_criteria.yaml`

```yaml
# 降雨验证标准
precipitation:
  min_value: 0.0
  max_value: 100.0
  max_daily_value: 500.0
  max_spatial_cv: 0.5
  min_spatial_correlation: 0.3
  max_missing_ratio: 0.1
  max_consecutive_zeros: 24

# 空间验证标准
spatial:
  min_area_km2: 1.0
  max_area_km2: 10000.0
  allow_invalid_geometry: false
  min_valid_geometry_ratio: 0.95

# 时间序列验证标准
timeseries:
  max_missing_ratio: 0.1
  max_consecutive_missing: 24
  min_value: 0.0
  max_value: 1000000.0
  max_hourly_change_ratio: 0.5
  max_daily_change_ratio: 2.0

# 水文过程验证标准
hydrologic:
  min_runoff_coefficient: 0.0
  max_runoff_coefficient: 1.0
  water_balance_tolerance: 0.05
```

### 使用验证框架

```python
from hydrosis.validation import (
    validate_precipitation_data,
    validate_runoff_coefficient,
    validate_water_balance
)

# 验证降雨数据
precip_result = validate_precipitation_data(precipitation_df)

# 验证径流系数

    print(f"径流系数异常: {rc_result.errors}")

# 验证水量平衡
wb_result = validate_water_balance(
    precipitation_mm=500,
    runoff_mm=325,
    evapotranspiration_mm=150,
    storage_change_mm=20,
    tolerance=0.05
)
```

## 常见问题

### Q1: 径流系数大于1怎么办？

**原因**: 通常是降雨数据质量问题

**解决步骤**:
1. 运行诊断工具: `python diagnose_zone2_precipitation.py`
2. 检查空间变异系数 (CV)
3. 如果CV > 0.5，需要改进降雨数据:
   - 增加雨量站密度
   - 使用更好的插值方法
   - 使用实测数据替代合成数据

### Q2: 验证失败如何处理？

**示例**:
```
❌ 验证失败: 空间变异系数过大 0.65 > 0.50
```

**处理方法**:
1. **检查是否为真实问题**: 查看数据质量报告
2. **调整验证标准** (如果数据确实合理):
   ```yaml
   # validation_criteria.yaml
   precipitation:
     max_spatial_cv: 0.7  # 放宽标准
   ```
3. **改进数据质量**: 见Q1

### Q3: 如何提高模拟效率？

**方法1: 使用并行HBV**
```python
from hydrosis.runoff.parallel_hbv import ParallelHBVConfig

config = ParallelHBVConfig(
    max_workers=8,  # 增加worker数量
    show_progress=True
)
```

**方法2: 性能基准测试**
```bash
python test_parallel_hbv.py
```

**方法3: 减少输出频率**
```yaml
output:
  save_hourly: false
  save_daily: true  # 只保存日数据
```

### Q4: 配置文件路径错误

**错误**:
```
FileNotFoundError: config/workflow_config.yaml
```

**解决**:

```bash
cd /path/to/HydroSIS

python script.py --config /absolute/path/to/config.yaml
```

### Q5: 如何自定义HBV参数？

**方法1: 修改配置文件**



**方法3: 运行校准**

## 性能参考

基于不同规模流域的性能数据:

| 分区数 | 时间步数 | 串行时间 | 并行时间(4核) | 加速比 |
|-------|---------|---------|--------------|--------|
| 10    | 120     | 5.2秒   | 3.1秒        | 1.68x  |
| 50    | 120     | 26.5秒  | 8.9秒        | 2.98x  |
| 100   | 120     | 53.1秒  | 15.7秒       | 3.38x  |
| 200   | 240     | 212.3秒 | 61.2秒       | 3.47x  |

**建议**:
- 分区数 < 10: 串行执行
- 分区数 10-50: 2-4核并行
- 分区数 > 50: 4-8核并行
